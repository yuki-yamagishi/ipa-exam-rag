# IPA Exam RAG (自己成長型 RAG システム)

情報処理技術者試験（IPA）の高度試験・過去問を対象とし、単なる検索（Read）にとどまらず、対話・解説から得た知見を自律的に精査・構造化してナレッジベースへ再インデックス（Write）する自己成長型 RAG システムです。
システムアーキテクト（SA）午前II問題を対象とし、FastAPI バックエンドと Vite + React 19 モバイル特化 SPA により単一コンテナで高速稼働します。

---

## 🎯 スコープと設計意図 (Scope & Design Intent)

本システムは、**開発者自身のシステムアーキテクト試験合格を目的としたシングルユーザー（個人利用）特化システム**です。過剰なエンジニアリングを排し、個人運用における経済合理性とセキュリティを両立させる明確な設計意図を持っています：

1. **インフラコストの極小化 (Single-Instance & SQLite)**:
   - 高価なマネージド DB（Cloud SQL 等）やメッセージブローカーをあえて排除し、軽量な SQLite ＋ GCS FUSE（最大インスタンス数 1 固定）で運用することで、月額インフラ費用を極小化しています（[ADR-0004](docs/adr/0004-sqlite-automatic-schema-migration-and-single-instance-constraint.md)）。
   - クリーンアーキテクチャの Repository パターンにより、将来マルチユーザー化が必要になった場合も上位ロジック無破壊で PostgreSQL 等へ切り替え可能な移行パスを担保しています。
2. **外部公開時の課金保護 (Secure by Default & Fail-fast Guard)**:
   - 外出先（スマートフォン）からの演習を可能にするため Cloud Run にデプロイする一方、第三者による Gemini API の不正利用・課金搾取を防止するため、**Google OAuth 2.0 認証を既定で有効化（Secure by Default）**しています。
   - Cloud Run 実行環境（`K_SERVICE` 検知）において誤って認証を無効化（`AUTH_ENABLED=false`）して起動することを物理的に遮断する起動ガードレールを備えています（[ADR-0005](docs/adr/0005-cloud-run-serverless-execution-and-google-oauth-architecture.md)）。
3. **あえて行わないこと (Non-Goals)**:
   - マルチテナント分離・細粒度の権限管理（RBAC）: 個人利用であるため過剰設計を排除。
   - 分散トランザクション・外部セッションストア: 暗号署名 Cookie で自己完結。

## 1. 主要機能 & アーキテクチャ

- **🥋 過去問道場 演習機能**: スレートダーク調の読解専用カード、親指操作（56px タッチ領域）、即時正誤判定、中断セッション再開、公式解説からの AI 質問連携。
- **📖 過去問ブラウズ & 検索**: 125 問全問の自由閲覧、年度/分野フィルター、500ms デバウンス検索。
- **💡 AI に質問 (RAG 対話)**: SSE 低遅延ストリーミング文字送り（0.5秒未満）、Qdrant 参照元 Citation アコーディオン自動展開、即時トースト付きバックグラウンド知見保存（HTTP 202 Accepted）。
- **📚 マイ知見ノート**: 対話から自律獲得した合格知見（核心概念、誤答トラップ、実務指針）の 3 軸構造化閲覧・タグ検索。
- **📊 学習傾向・弱点分析**: 総合正答率、合格ライン（60%）比較、分野別習熟度プログレスバー、苦手問題ランキング、直近解答履歴ログ。
- **⚙️ システム設定 & 認証**: API キー動的更新、Qdrant 全問再インデックス、履歴初期化（二段階確認）、Google OAuth 2.0 ログイン管理。
- **🐳 Multi-stage Docker 統合**: Node.js 20 ＋ Python 3.12 の 3 ステージ構成、non-root 実行 (`appuser`)、SPA HTML5 History API Fallback、Cloud Run `--no-cpu-throttling` 完全対応。

## 2. 収録データセット（シードデータ）の仕様と位置づけ

システムアーキテクト（SA）試験は、基本情報や応用情報のような汎用過去問道場 Web サービスが公式に存在しない区分です。本システムでは、以下の仕様に基づいて編纂された実戦演習データセット（全125問）をシードデータとして収録しています：

- **出題範囲の網羅**: IPA システムアーキテクト試験午前IIシラバス（システムアーキテクチャ設計、マイクロサービス、分散トランザクション、イベント駆動、モデリング、セキュリティ、性能設計等）を網羅。
- **公式実施期の反映**:
  - 2021年度（令和3年）：秋期（25問）
  - 2022年度（令和4年）：秋期（25問）
  - 2023年度（令和5年）：**春期**（25問、IPA試験改編スケジュールに準拠）
  - 2024年度（令和6年）：**春期**（25問）
  - 2025年度（令和7年）：**春期**（25問）
- **RAG グラウンディング特化の解説構造**: 単なる正解番号の提示にとどまらず、各設問の解説（`explanation`）に「正解の論理的根拠」と「誤答選択肢の技術要素（Saga、CQRS、イベントソーシング、サーキットブレーカー等）の対比解説」を緻密に付与。LLM による知見抽出（Judge Agent）と Qdrant ベクトル検索に最適なナレッジベースを形成しています。

## 3. ローカル開発クイックスタート

### 3.1. バックエンド起動 (FastAPI)

```bash
# 依存関係のインストール (uv 使用)
uv sync --extra dev

# 環境変数ファイルの作成（ローカル開発では AUTH_ENABLED=false が設定済み）
cp .env.example .env

# テスト実行
uv run pytest

# 静的解析 (Ruff)
uv run ruff check .

# バックエンドサーバー起動 (http://localhost:8080)
uv run uvicorn src.presentation.api.main:create_app --factory --port 8080 --reload
```

> **認証は既定で有効です。** `AUTH_ENABLED=false` はローカル開発専用で、Cloud Run 上で指定するとアプリは起動を拒否します。

### 3.2. フロントエンド起動 (Vite / React 19 SPA)

```bash
cd frontend

# 依存関係のインストール
npm install

# 単体テスト実行
npm test

# 型検査
npm run typecheck

# 開発サーバー起動 (http://localhost:5173)
npm run dev
```

### 3.3. Docker 単一コンテナ本番ビルド & 起動

```bash
# マルチステージ Docker ビルド
docker build -t ipa-exam-rag .

# コンテナ起動 (ポート 8080)
docker run -p 8080:8080 -e GEMINI_API_KEY="your_api_key_here" ipa-exam-rag
```

ブラウザで `http://localhost:8080` にアクセスすると、統合 SPA が表示されます。
