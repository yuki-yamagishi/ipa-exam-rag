# Issue #1: 過去問題の出典明記の是正およびREADME章立て階層の復元

## 1. 解決すべき課題・背景 (Problem Statement / Why)
- **現在の問題点**:
  - IPA（独立行政法人情報処理推進機構）の公式過去問題使用ガイドラインでは、過去問利用時に「年度、期、試験区分、時間区分、問番号」を明記した出典（例:「出典：平成31年度 春期 基本情報技術者試験 午前 問1」）の記載が義務付けられている。現在の README.md および data/seeds/README.md では権利帰属先のみが記述され、公式指定の出典表記書式および問題の改変有無（独自解説の付与など）が明示されていない。
  - README.md の章立てにおいて、「3. ローカル開発クイックスタート」の下位見出しが「2.1」「2.2」「2.3」と誤っており、さらに後続の「ドキュメント体系」も「3.」と重複採番されているため、ドキュメントの章番号階層が破綻している。
  - フロントエンド画面（演習カード、過去問ブラウズカード、知見モーダル）において、IPA公式指定書式に準拠した出典表記が統一的に表示されていない。
- **放置した場合のリスク**:
  - IPAの公表問題利用条件への不適合リスク。
  - 公開リポジトリとしてのドキュメント品質・信頼性の著しい低下。
  - ユーザーが過去問の出典や独自解説の境界を正しく認識できないリスク。
- **なぜ今解く必要があるのか**:
  - 本リポジトリは公開ポートフォリオとして運用されており、ライセンス・著作権・出典の正確性はコンプライアンス上の最重要要件であるため。

## 2. 期待される成果と価値 (Desired Outcome / Value)
- README.md および data/seeds/README.md に、IPA公式指定に完全準拠した過去問題の出典明記規則と具体例、著作権の不放棄、教育目的での利用、および独自作成解説の所在が明記される。
- README.md の見出し番号が 1 から 5 まで論理的一貫性を持って整流化される（3.1, 3.2, 3.3, 4, 5.1, 5.2）。
- フロントエンドに共通ユーティリティ（`formatQuestionSource`）を整備し、問題演習カード、問題一覧ブラウズカード、知見詳細モーダルにおいて IPA 公式指定書式（「出典：令和X年度...」）で一貫して表示される。

## 3. 排除するリスク (Risks to Eliminate)
- IPA公式過去問題使用ガイドラインからの逸脱リスクの排除。
- READMEの目次・章番号不整合による可読性・構造信頼性喪失の排除。
- フロントエンドコンポーネント間での出典表記のバラつき・表記揺れの排除。
- 既存のテストスイート（バックエンド pytest、フロントエンド vitest）の回帰破損の防止。

## 4. スコープの定義 (Scope & Boundaries)
- **スコープ内 (In-Scope)**:
  - README.md の章立て見出し番号の是正（3.1, 3.2, 3.3, 4, 5）。
  - README.md および data/seeds/README.md における IPA 公式ガイドライン準拠の出典表記・権利帰属・独自解説方針の明記。
  - フロントエンドにおける和暦変換・出典表記ユーティリティの実装と単体テスト。
  - フロントエンドの QuestionCard、QuestionBrowseCard、InsightDetailModal への出典表記の適用。
- **スコープ外 (Non-Goals)**:
  - 過去問シードデータ JSON の問題文・選択肢本文の大規模改変。
  - 新規試験区分（AP, FE等）のデータ追加。

## 5. 受け入れ基準 (Acceptance Criteria / Definition of Done)

### 5.1. 機能受け入れシナリオ (Feature-specific Acceptance Criteria: Given-When-Then)
- **シナリオ 1: README.md の章番号階層が完全に整流化されていること**
  - **Given (前提)**: README.md をトップレベルから通読する。
  - **When (操作・入力)**: 各見出しの章番号を検査する。
  - **Then (期待結果)**: 「## 1. 主要機能 & アーキテクチャ」「## 2. 収録データセット（シードデータ）の仕様と位置づけ」「## 3. ローカル開発クイックスタート」「### 3.1. バックエンド起動」「### 3.2. フロントエンド起動」「### 3.3. Docker 単一コンテナ本番ビルド & 起動」「## 4. ドキュメント体系」「## 5. 権利帰属・著作権・出典および免責事項」「### 5.1. 過去問題の出典明記および知的財産権の帰属」「### 5.2. 免責事項」の順序で重複なく連続している。
- **シナリオ 2: IPA公式指定の出典表記がドキュメントに明記されていること**
  - **Given (前提)**: README.md および data/seeds/README.md の権利帰属セクションを開く。
  - **When (操作・入力)**: 出典に関する記述を確認する。
  - **Then (期待結果)**: 「出典：令和X年度 [春期|秋期] システムアーキテクト試験 午前Ⅱ 問Y」の形式で明記規則と具体例が記載され、IPAが著作権を放棄していないこと、教育目的での利用であること、解説文は本プロジェクト独自作成であることが明記されている。
- **シナリオ 3: フロントエンドユーティリティによる公式出典文字列の生成**
  - **Given (前提)**: 2021年秋期問1の設問オブジェクト（year: 2021, term: "秋期", exam_type: "SA", question_number: 1）を入力とする。
  - **When (操作・入力)**: `formatQuestionSource` 関数を呼び出す。
  - **Then (期待結果)**: "出典：令和3年度 秋期 システムアーキテクト試験 午前Ⅱ 問1" という文字列が返却される（exam_type が "SA" の場合の時間区分は "午前Ⅱ" と判定付与される）。
- **シナリオ 4: 知見モーダルにおける source_question_id からの出典生成とフォールバック**
  - **Given (前提)**: `LearnedInsight` の `source_question_id` として "2021-SA-AM2-Q01" が渡される。
  - **When (操作・入力)**: `formatQuestionSourceFromId` 関数（または `formatQuestionSource` の ID 受付）を呼び出す。
  - **Then (期待結果)**: "出典：令和3年度 秋期 システムアーキテクト試験 午前Ⅱ 問1" が返却される。
- **シナリオ 5: 異常系・形式不一致・境界値における安全なフォールバック**
  - **Given (前提)**: 和暦対象外の年（例: year: 2018）、未知の試験区分コード（例: exam_type: "UNKNOWN"）、または形式外の ID（例: "custom-note-001"）が入力される。
  - **When (操作・入力)**: 出典フォーマッタ関数を呼び出す。
  - **Then (期待結果)**: 例外を送出せず、年が2018の場合は西暦表記（"出典：2018年度 ...")、未知の exam_type はコード値そのまま、形式外 ID は "出典: custom-note-001" として安全にフォールバック表示される。
- **シナリオ 6: フロントエンドUIにおける公式出典の表示**
  - **Given (前提)**: 過去問演習画面（PracticeScreen）、過去問ブラウズ画面（QuestionsScreen）、および知見詳細モーダル（InsightDetailModal）を表示する。
  - **When (操作・入力)**: 各設問カードおよびモーダルの出典表示を確認する。
  - **Then (期待結果)**: 公式出典フォーマット（「出典：令和X年度...」）が表示される。
