# ADR-0002: 自己成長型 RAG パイプラインと 2 段階知見審査アーキテクチャ

- **ステータス**: Accepted
- **決定日**: 2026-09-15

---

## 1. 背景と課題 (Context & Problem Statement)

情報処理技術者試験（IPA）の学習において、過去問の解説や対話から得た気づき・解法テクニックは極めて貴重な学習資産である。
しかし、一般的な RAG システムは「ナレッジベースからの情報検索（Read）」のみに特化しており、ユーザーとの対話で深化させた知見をシステム自身が学習して蓄積するループ（Write）が存在しない。

この課題を解決するために「自己成長型 RAG」を設計するが、以下の重大なリスクが存在する：
1. **ハルシネーションのナレッジ汚染リスク**:
   対話から抽出された誤った解説や不正確な概念がそのままベクトルストアに登録されると、次回以降の検索ノイズとなり、システム全体の回答精度が加速度的に劣化する。
2. **重複知見による検索効率低下リスク**:
   類似した知見が多数登録されると、Top-K 検索の枠を同一内容が占有し、多様な観点からの情報提供が妨げられる。
3. **API レート制限および一時障害リスク**:
   LLM API のレートリミット（429 Too Many Requests）や一時的なサーバーエラー（503 Service Unavailable）によって処理が中断されるリスク。

---

## 2. 検討した選択肢 (Considered Options)

1. **選択肢 A: 2 段階審査（LLM Judge Agent ＋ Cosine 重複排除）＋ 指数バックオフリトライ（採用）**
2. **選択肢 B: ユーザーによる全件手動承認制**
3. **選択肢 C: 無審査による自動追記**

---

## 3. 決定事項 (Decision)

**選択肢 A を採用する。**

### 3.1. 3 軸構造化ナレッジモデル (`LearnedInsight`)
対話から抽出する知見を非構造化テキストではなく、以下の 3 軸に厳格に構造化する：
- **`core_concept` (核心概念)**: 本質的な定義、アルゴリズム、標準仕様。
- **`trap_analysis` (誤答トラップ分析)**: 受験者が陥りやすい典型的な誤解や選択肢の引っかけ構造。
- **`practical_takeaway` (実務・試験での即応指針)**: 問題文の着眼点や判断基準。

### 3.2. 2 段階知見審査パイプライン
1. **第 1 段階: 抽出 (Extraction)**:
   対話履歴から上記 3 軸を満たす知見候補（`KnowledgeCandidate`）を生成。
2. **第 2 段階: 審査 (Judge Agent)**:
   独立した審査プロンプトにより、出題元の正解根拠と照合して客観的確信度スコア（`confidence_score` 0.0〜1.0）を算出。**閾値 0.85 以上のもののみ承認（is_approved: True）** とする。
3. **第 3 段階: 重複排除 (Deduplication)**:
   承認された知見のベクトル埋め込みを生成し、既存知見とのコサイン類似度を算出。**類似度 0.88 以上の既存知見が存在する場合は新規登録せず、既存知見のタグ拡充や関連情報マージにとどめる**。

### 3.3. LLM API 呼び出しの堅牢化
- **指数バックオフ**: 一時障害・レート制限に対して、最大 3 回の指数バックオフリトライ（初期遅延 1.0 秒、係数 2.0）を実施。
- **モデルフォールバック**: プライマリモデル（Gemini 3.7 Flash）が利用不能な場合は、フォールバックモデル（Gemini 3.5 Flash Lite）へ安全に切り替える。

---

## 4. 影響と結果 (Consequences)

### ポジティブな影響
- **ナレッジベースの高純度維持**: 厳格な 2 段階審査により、不正確・無価値な情報の登録が自動排除される。
- **自律的進化**: 対話を重ねるほど、過去問の出題意図や受験生の弱点に即した高品質なナレッジが自律的に拡充される。
- **高い耐障害性**: 指数バックオフとフォールバックにより、API の一時的障害によるユーザー体験の中断を防止。

### トレードオフ・留意点
- 審査および重複排除の計算により、知見登録処理に数秒のレイテンシが生じる。この問題は、FastAPI の `BackgroundTasks` を用いた非同期処理（HTTP 202 Accepted 即時返却）により解決する（ADR-0003, ADR-0005 参照）。
