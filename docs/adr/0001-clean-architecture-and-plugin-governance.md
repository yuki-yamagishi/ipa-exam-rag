# ADR-0001: クリーンアーキテクチャの採用と Antigravity プラグインガバナンス

- **ステータス**: Accepted
- **決定日**: 2026-09-15

---

## 1. 背景と課題 (Context & Problem Statement)

IPA Exam RAG は、情報処理技術者試験（基本情報・応用情報・高度試験）の過去問、シラバス、および対話から得た知見を管理・検索するシステムである。

本システムを長期にわたり高信頼・高保守性で運用・拡張していくにあたり、以下の課題が存在する：
1. **外部依存との密結合リスク**:
   LLM プロバイダー（Gemini API）、ベクトルデータベース（Qdrant）、リレーショナルデータベース（SQLite）、および Web フレームワーク（FastAPI）等の具象実装にビジネスロジックが直接依存すると、技術スタックの刷新やテストが極めて困難になる。
2. **自律開発における品質逸脱リスク**:
   AI エージェントによる開発において、「注意深く作業する」という人間の精神論に頼ると、仕様破壊、未テストコードの混入、不要なパッチワーク修正が不可避的に発生する。逸脱した瞬間に物理的にコマンドや実行を拒絶・ブロックする客観的なガバナンス基盤（Mechanisms）が不可欠である。

---

## 2. 検討した選択肢 (Considered Options)

1. **選択肢 A: クリーンアーキテクチャ 4 層構造 ＋ Antigravity プラグインガバナンス（採用）**
2. **選択肢 B: フレームワーク駆動のモノリシック構成（FastAPI 標準 MVC）**
3. **選択肢 C: マイクロサービス構成**

---

## 3. 決定事項 (Decision)

**選択肢 A を採用する。**

### 3.1. クリーンアーキテクチャ 4 層構造と依存性逆転の徹底
システムを以下の 4 つの独立したレイヤーに分離し、依存関係の方向を「外側から内側」への単一方向に物理制限する：

1. **Domain Layer (`src/domain/`)**:
   - 外部ライブラリに一切依存しない純粋なビジネスエンティティ（`ExamQuestion`, `LearnedInsight`, `PracticeSession` 等）および抽象インターフェース（`IQuestionRepository`, `IVectorStore`, `ILLMProvider` 等）のみを定義する。
2. **Application Layer (`src/application/`)**:
   - ユースケースロジック（`PracticeService`, `RAGService`, `SelfGrowthService`, `AnalyticsService`）を担う。ドメインインターフェースのみを操作し、具象インフラを知らない。
3. **Infrastructure Layer (`src/infrastructure/`)**:
   - ドメインインターフェースの具象実装（`GoogleGenAIProvider`, `QdrantVectorStore`, `SQLiteHistoryRepository`）を担当する。外部 SDK や DB ドライバをここにカプセル化する。
4. **Presentation Layer (`src/presentation/`)**:
   - 外部との接点（FastAPI ルーター、API スキーマ、依存性注入コンテナ）を担当する。

### 3.2. 純粋プラグイン設計によるエージェントガバナンス
エージェント管理用・開発支援用のスクリプトをプロジェクトルートに平置きせず、`.agents/plugins/antigravity-review-loop` に独立した Git Submodule としてカプセル化する。
以下のライフサイクルフックにより、開発プロセスを物理的に統制する：
- `branchDoRGate`: 要件定義（Why・排除リスク・受入シナリオ）が完備されるまでトピックブランチ作成を物理ブロック。
- `safetyGuard`: エージェントによる本番マージの直接実行や危険なコマンドを物理ブロック。
- `prePrAuditGate`: PR 作成前の仕様整合性・全量テスト・DoD 完了を自動検証。

---

## 4. 影響と結果 (Consequences)

### ポジティブな影響
- **100% の単体テスト容易性**:
  ドメイン・アプリケーション層はインフラのモックを注入することで、外部 API やネットワークに接続することなく高速かつ完全にテスト可能。
- **技術スタックの交換可能性**:
  LLM プロバイダーやベクトルストアを変更する場合でも、Infrastructure 層の 1 クラスを新規作成するだけで完了し、コアドメインに一切影響を与えない。
- **仕様破壊のゼロ化**:
  CI およびプラグインフックにより、精神論を排した機械的クオリティゲートが常時機能する。

### トレードオフ・留意点
- インターフェース定義と DTO 変換が必要となり、初期ファイル数は増加するが、システムの拡張性と堅牢性により十分に相殺される。
